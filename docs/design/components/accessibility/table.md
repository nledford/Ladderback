# The table

- `SortableTable` (a real `<table>` with a `<caption>`, `scope`d headers and a sort button whose result is announced politely), since replaced by `Table` (below).

- **The table** is `Table` (`components/table.rs`), which replaced `SortableTable`, and every table of the app is one (#876): Operations, Repositories, the plans, the start page's plans, API tokens, the Log, a repository's snapshots and its stats, the forget review's lists and a proposal's forget preview. It is a real `<table class="data-table">` inside a frame, `<div class="data-table-frame" role="region" tabindex="0">`, named as the table is (`Name::Caption` or `Name::Heading`).

  What it decides is `components/table/rules.rs`, on the host. `press` sorts a column the way it first sorts, ascending unless the column is `descending_first` (as Operations' Started is, its history arriving newest first), the same column again the other way, and another column its first way whichever way the last ran. `aria_sort` and `glyph` follow it (`arrow-up-down`, `arrow-up` and `arrow-down`, from Lucide's `arrows` category). `order` is a stable sort on each row's `SortKey`, a number, a text compared by its bytes or an instant compared as the time it is, read once a row, so rows that tie keep the order given either way. It drops a key an earlier row has, keeping the first row, and `positions` points each key at that row, so a repeat in the daemon's data never reaches the keyed `<For>` (#138). `shown` says what takes the table's place: loading, unreachable, empty, or the table.

  Rows are keyed (`key`, the caller's) and drawn by a keyed `<For>` over the order, each built once as it first shows. Its cells bind to a memo of the row found by its key, so a change reaches only what a cell binds to, and only a change of `shown` builds the table again.

  A row that moves (a sort, or a change to the sorted column) is taken out and put back, and a moved node loses focus in every engine. So the table notes the element focused in its body before it applies a new order and gives focus back after the move: in the same turn, and again at the next frame.

  A column given `Column::cued` (a `Cue`: what a live update can change in a row, and the words that say a row is marked; the Operations page cues its status, and the first cued column counts) lights a row whose value changed while it showed, once, and marks it "changed, not yet seen" until it is seen (decisions 129 and 130). `features/ui/change_cue.feature` checks it on the Operations page and `features/ui/components/table.feature` on the gallery's Live table.

  `rules::cues` decides a change on the host: a row's first sight (the first rows, a row that arrives, the table built again) only seeds the value, and a value left as it was changes nothing, so a re-sort, a progress report and a paused page light and mark nothing. `rules::Marks` keeps which rows are unseen: focus entering a row sees it, a change while focus is in the row is seen as it comes, and a row that leaves takes its mark with it.

  The row carries `data-cue`: `"lit"` for the first frame drawn after the change, `"settling"` from two frames on, and `"settled"` once its cells' fade ends or is cut short (a transition inside a cell, such as a progress bar's, doesn't count). `style.css` fills the cells in the cue's fill (`--cue-fill`) while lit and gives them the 600 ms fade only while settling, so a change of theme reaches a settled row at once. The fill is on the cells because the pinned row header's own would cover the row's, and there is none under forced colors.

  A marked row carries `data-unseen` and its cued cell `data-cued`: the cell reads in bold, the row header draws a 3 px `--cue` edge at the row's start (`CanvasText` under forced colors), and the cell says the `Cue`'s words after its own, in a `sr-only` span (1.3.1), which the frame holds as below.

  The marks are a `ChangeMarks`, which the page makes and gives both the `Table` (`marks`; a table given none keeps its own) and a `MarkAllSeen` in the page's row of actions before the table. The button is always rendered and, while nothing is marked, hidden with its room kept (`invisible` and `inert`), so it moves nothing as it comes and goes. Its press marks every row as seen, says how many politely, and hands focus to the element its `then_focus` names: the page's heading.

  Each column has a fixed width in rem on its `<col>` (`table-layout: fixed`), and the table is `max(100cqi, the widths added up)`: the frame's width (`.data-table-frame` is an inline-size container, so `cqi` is the frame's), or the columns' where that is wider, and the frame scrolls. On a wide frame the columns share its spare width in proportion. No container query rule is needed: the unit alone measures the frame, and no column's width follows its content (#194).

  The frame is also the containing block (`relative`) of every box a cell places absolutely: the `sr-only` word of a marked row, the note an outside `Link` says after its words (`sr-only` too), any other out-of-sight box. Such a box is 1 px, so it shows nothing, but an absolutely placed box escapes the `overflow` clip of every box that isn't positioned, and its place, past the columns scrolled out of view, would otherwise count in the page's own width: at 320 px with 200 % text an outside link in the live table demo's last column widened the page by 1016 px, so it scrolled sideways (1.4.10). With the frame positioned, the box counts only in the frame's scroll width. `table.feature` checks it with both kinds of box in one row.

  A caption is as wide as its table, so where the frame scrolls it would run on past the frame's end and be cut off: at 320 px with 200 % text a hub's "Plans of …" caption showed "Plans of demo-tabl", 1382 px wide inside a 256 px frame (#1695). Its words sit in a box inside the `<caption>` that is at most the frame's width (`max-inline-size: 100cqi`) and pinned at the frame's start (`position: sticky; inset-inline-start: 0`), so the table's name wraps within the frame and reads whole however far the frame has scrolled. The caption stays the table's `<caption>`, so the table and its frame keep their names, and the box, a `<span>`, adds nothing to the accessibility tree. `table.feature` checks it on the gallery's narrow and right-to-left tables, before and after the frame scrolls to its end.

  No word breaks inside unless it is longer than its whole column (#524): the body's `overflow-wrap: anywhere` stays, and in a fixed table no column narrows below its rem, so where the columns are wider than the page the frame scrolls and no word is broken to fit, while a word longer than its column (a 64-digit ID, a long log source) breaks rather than run over the next cell. An address breaks between its parts first, where `address_view` marks them. The pinned headers' column is at most 40 % of the frame, so there a word wider than that breaks, as *Operation* at 320 px with 200 % text does. A header whose words must read whole, a snapshot's short ID or the Repositories page's *Name*, keeps their room instead (`Column::kept_whole`, below), and a word wider than that room still breaks, as a 40-letter repository name does.

  So no table has width rules of its own: the per-page rules of the Operations and Repositories tables, and their container queries, went with the move. A page's columns add up to no more than the room it has at 1280 px (58rem; 44rem for the API tokens beside the Settings tabs), so a wide screen never scrolls.

  A time in a cell is its words in a `<time datetime>` that gives the instant to a program (`time_view`): the full time is the cell's visible text, and no `title` or tooltip repeats or hides it (#851).

  Each row's header, and the corner header above them, is pinned at the frame's inline start (`position: sticky; inset-inline-start: 0`, the right in a right-to-left page) on the page's background (`Canvas` under forced colors). The row header column is at most 40 % of the frame (`min(<width>, 40cqi)`), and the frame's `scroll-padding-inline-start` is the room it covers. Browsers already scroll a control focused beneath a sticky header nearly clear of it, to within a pixel or two in Chromium, Firefox and WebKit; the padding scrolls it wholly clear, so it stays in view (2.4.11), at 320 px with 200 % text too, where the frame is 8rem wide.

  A row header kept whole (`Column::kept_whole`) keeps the room its words need however narrow its frame, up to three fifths of it, so the cells beside it keep two fifths to be read in (`min(<width>, max(40cqi, min(<room>, 60cqi)))`, and the padding likewise). A snapshot's short ID keeps 8rem: its eight hex digits in bold at their widest (DejaVu Sans Bold's "b" and "d", 0.72em each) with 1.4.12's letter spacing, and the cell's padding at its widest. At 320 px that is 52 % of the forget review's 244 px frame, and the ID reads whole (#1129); at 200 % text the frame is 180 px, and the ID breaks inside three fifths of it. Beside cells with controls, unlike a snapshot's time, the room is at most 4rem, half the 8rem frame at 320 px with 200 % text, leaving a focused control the rest (2.4.11): Repositories' *Name* (#1625).

  Borders are kept separate with no spacing, which draws as collapsed borders do while each cell keeps its own rule, so a pinned header carries its rule with it (a collapsed border belongs to the table and stays behind). The header row isn't pinned: the frame doesn't scroll vertically. A column at `Align::End` puts its header, cells and footer at the end of the line in figures of one width (`tabular-nums`).

  Its look is the incumbent's, refined rather than redrawn: full width, cells at the start and top, one Slate Note rule under each row, the caption in Slate Note, header text bold, flat. Taken from daisyUI's table: the pinned row header. Not taken from daisyUI or Flowbite: zebra stripes (DESIGN.md forbids them), a hover highlight on rows (rows aren't clickable; it would promise an action), an active row, shadows, a header band, built-in search, filters or pagination (#795 sits beside the table), checkbox selection, and density sizes.

  A table given `columns_choice` (a `ColumnsChoice`, the table's stable id) offers the Columns panel (decision 140). A Columns button before the frame (a Ghost Small `Button` with `aria-expanded` and `aria-controls`) opens a panel in the page's flow listing the columns after the row header's, in the table's order: each a `Checkbox` of its header words, Move up and Move down buttons named for it (unavailable at the list's ends, focus kept on the button pressed or handed to the other), and a drag handle a screen reader skips, then Reset columns. Each change is said politely. Escape closes the panel and hands focus to its button, after a tooltip's own Escape. Operations, Repositories, the plans, the Log and API tokens offer it; a repository's snapshots don't, since with one column besides the row header the panel would be noise.

  A table may also give columns it always shows (`always_shown`, decision 140 as amended for #1625): they stand right after the row header, in the order given, and the panel doesn't list them, so no choice of columns hides or moves them, a choice kept from before they came included (`Layout::from_kept` reads only the listed columns' ids). Only for the one fact a page exists to let a reader check, as who maintains each repository is on Repositories (I1). A footer's cells follow the table's places, so they count these columns first. The gallery's Table demo shows one, Kind, and `table.feature` hides every listed column beside it.

  The button's chevron, decoration beside its words, points down while the panel is closed and up while it is open. Where the panel has 28rem, its list is a grid whose rows share its columns, so the Move buttons line up however long a column's name is; with less, as at 320 px with 200 % text, each row wraps instead.

  What it decides is `rules::Layout`, on the host: the order and the hidden set, the Move buttons' ends, and what this browser kept (`ladderback-columns-<id>` in `localStorage`), read as outside input. The table draws its `<col>`s, headers, cells and footer in that order, keyed by column, and counts only shown columns in its width. Hiding the sorted column ends the sort (`rules::sort_kept`); a hidden cued column marks nothing, and hiding it sees its marks (`rules::seen_as_it_comes`). A drag is pointer events on the panel's list, the pointer captured by what it pressed in the handle, which alone has `touch-action: none`; `rules::gap_at` and `rules::drop_place` say where it lands, and a line at that gap, drawn only while it marks so forced colors paint no other, shows it. Dragging is never the only way (2.5.7): the Move buttons do it all.

  The gallery's "Table" demo, before the Tooltip's, has a choice of what the table shows (its rows, loading, empty or unreachable), a sortable table of demo folders with a total in its footer, an "Add a file to …" action in each row and the Columns panel, and the same table, unsorted, in a narrow frame and right to left.

  `features/ui/components/table.feature` checks sorting by Enter and Space, `aria-sort` and the sentence said, ties, and a row action keeping its focus as its row changes and moves. It checks the numbers' alignment, each state (the loading words just before the busy region and outside it), the frame scrolled by keyboard at 320 × 640 with 200 % text in both directions with each row header whole at its start, and the row headers' fill in light, dark and forced colors. `features/ui/tables.feature` checks each page's tables at 400 px: each sits in its own frame that Tab stops on, named as the table is, no word breaks inside unless it is longer than its cell's room, and no time hides in a `title`; the Operations and Repositories pages' own scenarios check 320 px with 200 % text.

  The same file checks the Columns panel on the gallery's demo by keyboard: its list and its unavailable ends, a column hidden and shown with its total, the sort a hidden column ends, the Move buttons and their focus, Reset columns, the choice kept across a reload, Escape, no sideways scroll at 320 px with 200 % text, and one drag by pointer in each engine.

  The 320 Rule's clip check (`ui-tests/steps/start_page.ts`) holds text inside a focusable, named region that scrolls inline to that region's scroll extent rather than to the viewport, and the region itself to the viewport. That is 1.4.10's allowance for a data table, and text an inner box cuts off still fails.
