  - `ModalDialog` (native `<dialog>` + `showModal()`, focus wrapped from the last tab stop to the first and Shift-Tab from the first to the last by a keydown handler on the dialog, Escape and the Close button both closing, focus returning to the invoker, and opens counted by the announcer).
    - *Opened by its owner* (#981). The owner opens and closes it through `open`, which the dialog clears however else it closes, Escape or its Close button (`close_label`, left out by a dialog that has none). It is named by its title, an `<h2>` by default (`title_level`, below), as the page beneath a modal is inert, and described by the element in it that `described_by` names. `fallback` names where focus goes when the control it returns to is gone. A `close` event that comes once the dialog has opened again is left alone, its closing already counted gone, so it never closes the dialog under the reader.
    - *A dialog under a section* (#989). `title_level` titles a dialog with an `<h3>`, for one that belongs to the section of the page that asked for it, as a review does. `returns_to` is the id of the control focus goes back to however the dialog closes, its owner clearing `open` too, rather than the element the browser remembers, which is gone when the page drew that control anew while the dialog was open; `fallback` then names where focus goes when no control has that id. The gallery's demo setting is titled at level 3 and draws its button anew once **Change the demo setting** is pressed, and focus returns to the new button; `features/ui/components/modal_dialog.feature` checks it by keyboard alone.
    - *A dialog that isn't simply dismissed.* `starts_on` is the button focus starts on; `on_cancel` takes Escape, the `cancel` event prevented, so the dialog stays open until its owner clears `open` (Chromium may still close it on a second Escape, which clears `open` as any close does); `on_close` runs on every close while the owner still shows the dialog, before `open` is cleared. The sign-in dialogs (§4.5, sessions) draw with it: the idle warning starts on **Stay signed in**, turns Escape into the request that keeps the session and closes once the daemon has answered; Sign in again holds the sign-in form, and its `on_close` tells a sign-in from giving up. The gallery's demo warning starts on **Keep the demo warning**, which Escape does too, and closes on **Answer the demo warning**; `features/ui/components/modal_dialog.feature` checks it by keyboard alone.
