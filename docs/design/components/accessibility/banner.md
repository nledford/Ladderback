# The banner

- **The banner** is `Banner` (`components/banner.rs`), for a page-wide notice above a page's content, something that stays true from page to page (sign-in off on the network, a pending update): an icon, then the words, its `children`. Its tone is a `BannerTone` (`components/banner/rules.rs`, decided on the host), the shared vocabulary's `Primary` (information, the default) or `Warning`, with Lucide's `info` and the status badge's `triangle-alert`, and a word that names each. The icon is an `Icon` labeled with that word, an image a screen reader hears before the words (1.4.1, A2). `Success` is left out, since a success is said once by a toast and lets go; `Error`, since a failure is stated once where it happened, never as a red banner (DESIGN.md); `Secondary`, which says no tone and has no icon of its own; and `Inherit`, which would leave only the words to tell the tone.
  - *Not a live region, not a landmark.* It has no `role` and no `aria-live`: a region that speaks whenever it is drawn speaks again on every page that draws it, and the page already has its announcer (A3). Nor is it `role="banner"`, the site header's landmark, or a named `region`, so it adds nothing to a screen reader's list of landmarks. It is never a stop for Tab; a button in it is.
  - *Dismissal.* A `BannerDismissal { remember_as, edition, then_focus }` ends the banner with a Ghost Small icon-only `Button` (Lucide's `x`) named "Dismiss", its name shown by a `Tooltip` (`Tip::Names`). A press takes the banner off the page; focus on the button as it goes moves to the element with the ID `then_focus` (`hand_focus_when_gone`), so it never falls to the page (2.4.3), and nothing is announced. The banner leaves through its own reactive branch, whose cleanup runs while the button is still on the page.
  - *Memory.* The press keeps `edition` in the browser's local storage under `ladderback-banner-<remember_as>`, one key per banner, as the language chosen is kept (`ladderback-language`). A banner drawn later, on this page or after a reload, stays away only while its key holds the very edition it would show (`stays_dismissed`), so a newer edition, such as the next pending update's version, shows again, and so does anything else the key holds. The memory is the browser's, never the daemon's: another browser or a private window shows the banner again, and a browser that refuses to keep it shows it again on the next load.
  - *The look.* Tailwind utilities (decision 117), logical ones only, and no rule of its own in `style.css`: a square strip of Ledger Gray (`bg-surface`) the width of the content, its words in the text's color (`text-fg`), its tone in the icon and in a 0.25 rem edge at the start of its line (`border-s-[0.25rem]` in `--tone`), so a warning is never a colored banner. The icon stands centered on the words' first line, the words wrap, a long path too, and Dismiss stands at the line's end. The contrast gate's pairs already cover it: `--accent`, `--warning`, `--fg` and the Ghost button's `--muted` are each 4.5:1 or more on `--surface`, so it adds no token and no pair. Under forced colors a 1px `CanvasText` edge all round keeps its box in view, the start edge still thick, and the icon takes the text's color.

  The caller's duties under WCAG 2.2 AA: what needs the reader now said through the announcer too (4.1.3); words that say what is so and what to do; `then_focus` kept on the page; a `remember_as` of its own for each banner, and an `edition` that changes when its words say something new.

  Taken from Flowbite's sticky banner, the reference (daisyUI has no banner): a strip across the page above the content, an icon, the words and a close button at the end. Not taken: sticking to the viewport as the page scrolls, which would cover content at 200 % text and on a small screen (1.4.10), a place at the bottom, call-to-action buttons and a colored fill.

  Every page-wide notice is a banner (#930), none of them dismissible, since each says what stays true until the reader acts: sign-in off, information on the start page and, on the network, a warning on every page, where its `id` (`sign-in-off-network`) lets each page's heading name it in `aria-describedby`; the available update, information, in the header; the missing Full Disk Access grant, a warning on every page whose link leads to the start page's steps and whose `id` (`full-disk-access-banner`) each page's heading names too (§4.4); the Repositories page's keyring note and the Pending changes page's note that approval is no safety boundary, warnings; and Settings' admin password that waits for a restart, information, or a warning when its file is damaged (`session::waiting_tone`).

  The pause banner stays `PauseUpdates`' own: it describes its button, beside it, edged in `--muted` so it never reads as a second focus ring.

  The gallery's "Banner" demo (`section#banner-demo`, an id that finds it under a pseudolocale too), after the Skeleton demo and before the Link demo, shows a banner in each tone, a long path that wraps inside the warning, and a dismissible notice, whose focus goes to the button that brings a newer edition of it.

  `features/ui/components/banner.feature` checks axe and the ARIA snapshot, that no banner is a live region nor holds one, each icon's name and its one shape per tone, no stop for Tab, Enter and Space on Dismiss (gone, nothing said, focus handed on, still gone after a reload), a newer edition shown again, a browser that keeps nothing showing it again after a reload, the square fill, words, icon and edge in light and dark colors, the edge and icon under forced colors, the edge, icon and Dismiss right to left too, and the parts inside the banner at 320 px with 200 % text.
