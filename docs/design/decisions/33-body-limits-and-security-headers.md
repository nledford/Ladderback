# Decision 33: Body limits and security headers

**A body limit per route class, enforced before any route runs, and a content security policy that names the entry page's inline script by its hash** (recorded 2026-11-10, §10.1; #15, #16). `/api/v1` takes 128 KiB, the web UI no body; one layer collects the body up to the limit, so a route that reads its body some other way is bounded too, and a body over it is `413` with `body-too-large` and the limit as an argument. Every response carries `Content-Security-Policy` (`default-src 'self'`, `script-src 'self' 'wasm-unsafe-eval'`, `frame-ancestors 'none'`), `nosniff` and `Referrer-Policy: no-referrer`, and none carries `Strict-Transport-Security`. Why: Trunk writes the script that starts the application into `index.html`, and has no option to emit it as a file (trunk-rs/trunk#288), so a fixed `script-src 'self'` would stop the UI; allowing `'unsafe-inline'` would void the policy; the daemon hashes the inline scripts of the page it serves, so the policy follows every build. The same policy refuses a `style` attribute, so the progress bar sets its width as a style property. The daemon serves plain HTTP on loopback, where HSTS would bind a browser to HTTPS for whatever else later listens on that address. The limit classes grow with the routes: a configuration import takes its own.
