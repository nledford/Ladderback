# Decision 103: Status badge icons

**A status badge draws its state's own Lucide icon before its label, its shapes from `lepticons-data` with the default features off and only the categories the icons are in. The icon is decoration: hidden from assistive technology, out of the tab order, in the text's color. It never moves, the running one either** (recorded 2026-11-15, §4.5, §8.1; decided by the maintainer on #384).

**Amended 2026-11-16 (the maintainer, #778):** the badge draws its icon with the shared `Icon` component (§4.5): decoration, in the Inherit tone, at the Small size. The `<svg>` root around the glyph's shapes is now `Icon`'s, not the badge's own; what the badge shows and what a screen reader meets are unchanged, and what "The `<svg>` root" below says of the root, its `1em` fallback and the wasm tests holds for `Icon`.

## Why

- **Never color alone (A2).** Components §4.5 asks a status badge for an icon with a shape of its own per state, besides its text and color, so a reader who can't tell the colors apart scans a table of badges without reading each label.
- **The icons.** The maintainer's: `clock` (queued), `loader-circle` (running), `circle-check` (succeeded), `triangle-exclamation-point` (succeeded with warnings), `circle-x` (failed), `circle-slash` (canceled), `circle-dashed` (no result). `lepticons-data` 0.1.2 has the warning icon under its earlier Lucide name, `triangle-alert`: the same glyph.
- **One crate of glyphs, measured.** `lepticons-data` gives every Lucide icon as a typed enum with its shapes, so a missing icon is a compile error, not a broken page. Its features are Lucide's categories, and every icon of an enabled one is compiled in, so only the five the badges need are on (267 icons); they add 2.7% to the release wasm and 2.4% to its brotli (§8.1). The maintainer approved it and `lepticons` on #384; `lepticons` adds only a Leptos `Icon` component the badge doesn't use, so it isn't a dependency. `just deny` passes `lepticons-data`.
- **The `<svg>` root is the badge's own.** The badge draws the root around the glyph's shapes (`Glyph::svg`, the crate's own markup, never outside input), with `width` and `height` of `1em` to keep it text-sized without the stylesheet. The wasm tests render the badge to HTML under Node, and tachys' `to_html` of any element panics without leptos's `ssr` feature (it renders the element's extra attributes, an empty `Vec<AnyAttribute>`, only there), so `ssr` is a wasm32 dev-dependency of `web`: the page trunk builds stays client-side only, and a wasm test of an `on:` handler would need another way to run.
- **Decoration beside the text.** `aria-hidden="true"`, so a screen reader reads the label once; `focusable="false"`, so no browser makes it a tab stop; stroked in `currentColor`, so the contrast gate's badge pairs cover it (A4); `1em` tall, so it grows with the text (1.4.4).
- **The running icon stands still.** An operation can run for hours while the page stays in use, and nothing on the page could pause a spinner, so a turning icon would fail WCAG 2.2.2 (Pause, Stop, Hide), whose exception for movement that is essential, or part of a short load, doesn't cover it. The label says it runs; `loader-circle` stays as the shape.
