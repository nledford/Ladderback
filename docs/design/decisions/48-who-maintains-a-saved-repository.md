# Decision 48: Who maintains a saved repository

**A repository created under a name is saved with `maintenance = "local"`, and a connected one with `local` only when the person turns on "Maintain this repository from this agent", off by default; otherwise it is saved with no `maintenance`, which asks for nothing** (recorded 2026-11-11, §4.2, §7.3, I1). Only a repository that asks for `local` is maintained here: forget, prune, check and adoption, and the preview of each, are refused with `maintenance-not-owner` for any other. A repository created here can be maintained by nothing else yet, so asking it is only friction. A repository that already exists may be maintained by another agent or the hub, and only one place may (I1), so maintaining it from here is the person's explicit choice, never a default; the checkbox's hint says what maintaining means and why to leave it off. `POST /api/v1/repositories` carries the choice as `maintain-here` (absent is `false`); `_init` needs none. An imported profile keeps its own rule (`local` only with `[forget] prune = true`, §6.2). There is no migration: a configuration v0.1.0 wrote has no `maintenance`, so after upgrading its repositories are not maintained here until `maintenance = "local"` is added to their entries; the Snapshots page and the refusal say how, and the release notes say so. Changing who maintains a saved repository from the UI, and asking for the hub, wait for the hub (M4b). Ownership is checked once, before a run reads the repository, not again as the run takes its slot: on a standalone agent the window is the run's own reads, and only the person who asked can edit the file during them. The hub's maintenance lease (M4b) is a grant that can lapse, so it must be checked again at the slot. Rejected: saving every connection with `local` (two machines connecting one repository would both prune it, breaking I1; without a hub nothing can rule that out, and the agent can only warn, §7.3); changing the `Maintenance` default to `local` (a configuration edited by hand, or a repository nobody chose to maintain, would start pruning silently); migrating v0.1.0 configurations to `local` (the same risk for every repository that another machine already maintains).
