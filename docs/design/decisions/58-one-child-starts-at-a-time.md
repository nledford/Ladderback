# Decision 58: One child starts at a time

**Every child process the daemon starts, a worker, a hook, a password command or the `rclone` that serves an `rclone:` repository the daemon opens itself, starts through one spawn gate per process: `spawn_gate::hold(|| command.spawn())`** (recorded 2026-11-11, §4.1, §10.2; #234, #255). The gate is a process-wide lock in the `spawn-gate` crate, held only for the start itself, not while the child runs. Whatever else makes a descriptor that is not close-on-exec from the start (a test's own pipe) makes it inside `hold` and marks it before it lets go. **A hook's pipes are let go through the gate too**, when the call returns, so no start in flight still holds a copy of their read ends. **The daemon waits for the gate off the runtime's threads** (`spawn_gate::hold_blocking`, on tokio's blocking pool).

Why:

- **A child inherits every descriptor of its parent that is not close-on-exec when it starts.** Where the platform has no `pipe2` (macOS), the standard library makes each pipe of `Stdio::piped()` in two steps, `pipe` and then `fcntl` for close-on-exec, so a child that another thread starts in between inherits both ends and holds them for as long as it runs. Starts that go one at a time can't: each start makes its pipes inside the call that starts the child, and they are close-on-exec before the next start begins. Linux makes its pipes with `pipe2(O_CLOEXEC)` and never had the moment; the gate costs it a lock around each start.
- **What a held pipe does.** A worker whose stdin another child holds never sees the end of its job spec and fails to start; a password command's pipe held by a hook gives the hook what the command prints; a hook's pipe held by another hook keeps a descendant's late write from failing (decision 34). The hooks test that checks the last failed under an in-process `cargo test` on macOS in 1 of 4 runs on main (#234), and an `@e2e` scenario's command that should have died of SIGPIPE exited 0 (#255).
- **One gate for the process, so a crate of its own.** The descriptor table is the process's, so every adapter that starts a child must share one lock; adapters never depend on each other, so the lock lives in a crate of its own that has nothing else in it. It is shared infrastructure, not an adapter: it implements no port, knows nothing of the domain, and an adapter may depend on it as on a library. The `@e2e` runner starts its own children through the same gate (#255), since it runs the adapters in its own process.
- **Letting go through the gate as well.** Where a start falls back from `posix_spawn` to `fork` and `exec` (on both platforms, for a program named without a path when the child's environment is cleared or sets its own `PATH`, as a hook's is), the forked child holds a copy of every descriptor of the daemon, close-on-exec or not, until its `exec`, and the start holds the gate until then. A hook whose pipes were let go in that moment had its descendant's late write go through instead of failing. In 50 in-process runs each of the hooks tests' binary on macOS, made for this decision: with only the starts gated, 9 of 50 failed (7 of 50 in an earlier set); with every test hook named by its full path (`posix_spawn`, no such moment), 0 of 50, and 0 of 50 for that test alone; with the pipes let go through the gate as well, 0 of 50. A drop that waits for the gate finds no such copy left.
- **Off the runtime's threads.** A start whose `exec` stalls (a script on a hung mount, the first scan of a new program) holds the gate until it is done, and every other start waits for it. A start or a release that waited on one of the runtime's threads would stop that thread's other tasks, the HTTP server's and the timers that end other hooks among them, so each waits on tokio's blocking pool instead, and a stalled `exec` parks blocking threads only. What the call hands the pool is done even if the call is dropped meanwhile.
- **rclone** (amended 2026-11-12, #319). For an `rclone:` repository, rustic's backend starts `rclone version` and then `rclone serve`, and reads the server's standard error until it says where it listens, all in one call (`RcloneBackend::new`) that hands back no child. The daemon opens a repository itself only to evaluate retention (§3.2), on a blocking thread. Built inside `hold`, that call held the gate until `rclone` served, with no time limit, and every other start waited as long; built outside it, the server could inherit another start's pipes, or another start its. So the engine starts the server itself (`crates/adapters/engine/src/rclone.rs`), as that call does at the pinned revision: each of the two starts holds the gate alone, and the waits for `rclone version`'s answer and for the server's address don't. The server's pipe is made inside its start, so it is close-on-exec before the gate lets go; `rclone version`'s, read no further than its first line, is let go through the gate, as a hook's are. Once the server says where it serves, the repository is rustic's own REST backend at that address, named `rclone:<path>` as rustic's backend names it (rustic's errors quote the name, and the server's port means nothing to a user), with a random user and password handed to the server in its environment, as rustic does, which the evaluation's redactor masks like the repository's secrets (rustic's errors can quote the address they are written in). The server is killed and reaped when the evaluation ends, and its output is read a capped line at a time and logged masked (I4). Other backends start nothing and are built as rustic builds them, outside the gate. Upgrading the `rustic_core` pin compares that copy with rustic's `rclone.rs`.

Rejected: closing or marking every descriptor above 2 in the child before `exec` (`pre_exec`), and `posix_spawn` with `POSIX_SPAWN_CLOEXEC_DEFAULT` (both need `unsafe`, which the workspace forbids, and the second a start of our own in place of the standard library's); a lock the composition root hands each adapter (a test, or a new adapter, that builds one without it starts unguarded); a lock per adapter (a worker and a hook could still start together). For rclone: a deadline on rustic's call inside the gate (the gate can't be let go before the call returns, and the call hands back no child to stop, so a deadline would fail the evaluation and leave the gate held); evaluating retention in a worker, which has a descriptor table of its own (a new job kind and a process for a rare open, and the decision is the daemon's, §3.2).

Not covered:

- A descriptor a library makes in two steps outside a start, such as a connection the HTTP server accepts or a socket it opens on macOS, can still reach a child that starts in that moment.
- A hook call that its caller drops, rather than one that returns, lets go of the pipes without the gate, since a drop can't wait (its unreaped hook is killed with its group).
- A password command's pipes are let go without the gate when the call ends. A start that forks in that moment copies the read end and closes it unread at its `exec`; meanwhile a write of the command's own descendant can go through rather than fail. Nothing reads it, so no secret goes anywhere (I4).
- An `rclone` that never says where it serves keeps the evaluation's blocking thread, and itself, until it exits. The use case stops waiting at its read timeout, but nothing stops the server meanwhile. It holds up no other start.
