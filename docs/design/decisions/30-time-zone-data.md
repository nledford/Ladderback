# Decision 30: Time-zone data

**The build carries the IANA time-zone database: the workspace turns on `jiff`'s `tzdb-bundle-always`** (recorded 2026-11-10, §3.2, §8.4). `jiff` opens the system's database when it finds one and the bundled copy only when it finds none. Why: with `jiff`'s defaults the bundle is on only for Windows and wasm, so on Linux and macOS a host without `tzdata` (`scratch`, or a base image that leaves it out; M5's image may be one) knew no zone, and daemon text read every zone as UTC with no warning, as a schedule that names a zone (M2) would have run at the wrong times. The other way, leaving the bundle out and making a missing database an error at startup, would make every image install `tzdata` and leave the browser's build to rely on a default. Cost: about 248 KB (0.7%) on the stripped release daemon (35,547,920 B before, 35,795,744 B after, macOS arm64, `--no-default-features`), and nothing on the web UI's wasm, which looks up no zone (1,306,384 B before, 1,306,354 B after). Limits: the bundle replaces a missing database, not a missing zone, so a system database without a zone (a Debian base with `tzdata` but not `tzdata-legacy` has no `Europe/Kiev`) leaves that zone unknown, and a zone that doesn't resolve must be refused where a person types it (M2's schedule form) and not read as UTC. The bundled rules are as old as the release, so the system's copy, which the operating system keeps current, wins when there is one.
