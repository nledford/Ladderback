# Decision 60: How a plan's next run is worked out

**A run is planned when the one before it starts, kept while the agent is away, and made up for once when the agent comes back; a cron expression's moments are wall-clock times, each run once, and a time the clocks skip runs when they jump** (recorded 2026-11-11, §5; #271). The domain service `NextRun` (§3.1) has two questions: `NextRun::after`, the run planned after one that started (or, for a plan scheduled for the first time, after now), and `NextRun::resume`, what becomes of the planned run when the agent starts or wakes. Nothing in it reads a clock or draws a number: `now` comes from the `Clock` port and the jitter's draw from the `Random` port. Where §5 was silent:

1. **A time the clocks skip runs at the instant they jump** (03:00 for a 02:30 in Berlin on the morning the clocks go forward), not shifted by the length of the jump (03:30). Every moment in the skipped stretch runs then, once: `*/15 * * * *` runs at 01:45 winter time, then at 03:00 and 03:15 summer time, and `0 2,3 * * *` runs once at 03:00.
2. **"A repeated hour runs once" holds for every moment, not only fixed times.** Each wall-clock moment runs the first time round: when Berlin's clocks go back, `*/30 * * * *` runs at 02:00 and 02:30 summer time, then at 03:00 winter time, an hour and a half later. The `croner` crate runs a schedule with a wildcard hour, such as `0 * * * *`, on both passes, and it carries a skipped moment past the jump only for a fixed time, so that `0,30 2 * * *` would not run at all that morning; Ladderback reads `croner`'s moments on the plain wall clock and maps them to instants itself, so one rule holds for every expression.
3. **Jitter** puts a run up to the schedule's `jitter` after its moment, in milliseconds, as the same share of that stretch as the draw is of every `u64` (a multiply and shift, no remainder). The stretch ends a millisecond before the schedule's following moment: a run never takes the place of the next moment's run, which would skip it. A catch-up runs at once, without jitter.
4. **`every`** is real time from the start of the last run, so a change of the clocks neither lengthens nor shortens it, and its zone plays no part. It is at least 1 minute (a cron expression's finest step) and at most 366 days, as a jitter is (`Interval`, refused as `ValueKind::Interval`). A plan scheduled for the first time runs one moment after now, never at once: late rather than early, and `NextRun::after` is always strictly after the instant it is given.
5. **Catch-up** is decided by the planned run, not by the last run: a planned run at or before `now` when the agent comes back was missed, and runs once, now (`Trigger::CatchUp`), however many moments passed. Asking from the planned run keeps a run within its jitter (the agent back at 10:02 for a run planned at 10:05 waits until 10:05) and catches up a plan that has never run. Without catch-up the missed runs are skipped for the first moment after `now`.
6. **A clock set back** leaves a planned run later than any moment after `now` could put it (the moment plus its jitter): the run is planned again from `now`. Waiting for it would skip every run until the clock caught up, a year of backups after a reset of the clock by a year; running at the clock's next moment can at worst run one moment of the schedule again.

Rejected: shifting a skipped time by the length of the jump (a later run than §5's "next valid time"); running a wildcard schedule on both passes of a repeated hour (two runs for one wall-clock moment, which §5 rules out); a new `every` plan running at once (an early run, and one `after` could not express strictly after its instant); trusting a planned run after the clock went back (a silent gap as long as the jump).
