# Decision 112: How no repository config, the half a server refused and a listing's failure are told

**A job whose engine finds no repository config file where it looked fails with a code of its own, `repository-config-not-found`, with rustic's words masked as its detail, which the API answers 404; `credentials-refused` names the half of a hot/cold repository whose server refused, and creating a hot/cold repository asks each half's server before any file of it is written; a snapshot listing or a folder read that failed is told by the code of its failure** (recorded 2026-11-16, §3.1, §4.1, §4.4; #525, #521, #637). A location with no repository failed `operation-failed` in rustic's words ("No repository config file found for …"); a hot half whose server refused the login was found only after the cold half was written, and named no half; and a listing with a wrong password answered `engine-unavailable`, while a Test and a forget preview answered `password-not-accepted` for the same cause.

**The maintainer's answers:** the code is named `repository-config-not-found`, since `repository-not-found` stays decision 53's empty folder, which offers Create; the API answers it 404, not 503, since a missing repository is a configuration to correct; marking the half's field in the web UI's form is out of scope.

**Amended 2026-11-21 (#836, proposed with the change; the maintainer may change any of it):** a listing, a folder read or a search the engine failed in its own words, with no more specific code, is `operation-failed` (422) with those words, which the engine masked (I4), as its detail, as the maintenance routes tell such a failure, over HTTP and through MCP. It was `engine-unavailable` (503), the words in the log alone. That told a person, or an AI agent, that the engine couldn't be reached, and suggested a retry, when rustic had answered with an error a retry usually doesn't cure; and one cause read two ways on two pages. `engine-unavailable` stays for an engine that couldn't be run at all. Items 6 and 8 say it.

Decided:

1. **The code.** `FailureReason::RepositoryConfigNotFound { detail }`, on the wire `repository-config-not-found`, with no arguments and rustic's words, masked (I4), as its detail: they say where the engine looked. For an OpenDAL `fs` root folder that isn't there (item 2), the detail is Ladderback's own words naming that folder. Its message (`error-repository-config-not-found`) says no repository was found at the location, to check that the location is the right one and that its drive, folder or server can be reached and read, and that a repository never created there has to be created first.
2. **Where it is told.** In the engine adapter's `open` (`crates/adapters/engine/src/worker/repository.rs`), when the repository doesn't open, and only after decision 85's refusal of the credentials and decision 53's look at the folders: when rustic's error says "No repository config file found", rustic_core's words for it, which come with no error code of their own. A folder that can't be read, a server or a store that holds no repository and a repository that lost its config all fail so, since nothing tells an empty place from one out of reach. An OpenDAL `fs` root folder that isn't there fails so too, before its backend is set up, which would make it (decision 53); one that can't be read fails `operation-failed`, as OpenDAL reports it, with no word of a config file.
3. **404.** The Repositories API, the maintenance routes, the snapshot listing and a snapshot's folder read answer `repository-config-not-found` with 404, as `repository-not-found`: the request was right and the daemon could do it, but there is no repository where the configuration says. The web UI's advice to try again stays `operation-failed`'s.
4. **The half.** `credentials-refused` takes an optional text argument `half`, `cold` or `hot` (`RepositoryHalf` in the domain, "Hot half, cold half" in §3.1), given only for a hot/cold repository; a repository with no hot half leaves it out, and its message is decision 85's. The operation log stores it among the error's arguments and refuses to read back a half that is neither. When rustic's error holds a 401 or 403 of a hot/cold repository, each half on a REST server, the cold one first, lists its keys to tell whose server refused, as decision 85's listing does; when no listing refuses, the refusal names no half.
5. **Creating a hot/cold repository.** rustic writes the cold half before the hot one. So before `init`, each half on a REST server, the cold one first, lists its keys once, with retries off: a 401 or 403 fails the job `credentials-refused` naming that half, and no file of the repository is written. The halves' backends are set up before that, as for every job, so an OpenDAL `fs` half's root folder that wasn't there is made, empty, as creating the repository would have made it; a later Create uses it. A half anywhere else is not asked, for decision 85's reasons.
6. **A listing, a folder read and a search** are told by the code of their failure, as a read for maintenance tells its own (`failed` in `src/composition/maintenance.rs`): `password-not-accepted`, `credentials-refused` and the other typed codes with their statuses, a secret's refusal as the Repositories API's, 404 for no repository, and a failure in the engine's own words as `operation-failed` (422) with those words, masked, as its detail (amended, #836). Only an engine that can't run stays `engine-unavailable` (503), by its code alone, its words in the log.
7. **The location report.** Decision 80's probe already tells a location that holds no repository as `not-a-repository`, so a repository of several locations says it per location; when none is usable, the job still fails `no-location-usable`.
8. **On the wire.** A new code and a new optional argument, a compatible change under §12.1. A client that matched `operation-failed` for a missing config sees `repository-config-not-found` instead, in a REST refusal, the operation history, a webhook and a hook's `LADDERBACK_ERROR`; a client of the snapshot listing that matched `engine-unavailable` sees the typed code, and for a failure in the engine's own words `operation-failed` with a 422 (#836).

Accepted:

- **Matching rustic's words.** Decision 85 rejected telling a refusal by them, since they say the same of a missing repository; here they are matched only once a refusal and an empty folder are ruled out, and they are all rustic gives. A rustic upgrade that rewords them turns the case back into `operation-failed`; the engine's tests at a missing folder and at a REST server holding no repository fail then, rather than the code going quiet.
- **One or two more requests to create a hot/cold repository on REST,** each one listing, and on a server that refuses, one more refused login for a lockout to count (decision 85).
- **A refusal that comes only while the halves are written,** as when the credentials change between the listing and the write, still leaves the cold half written: a retry then finds its config and fails `repository-exists`.

Rejected:

- **`repository-not-found` for every missing config.** It offers Create (decision 53), and at an unplugged drive or a server path out of reach, Create would make a new, empty repository in the old one's place.
- **503, as `credentials-refused` and `password-not-accepted`.** Those refuse a repository that is there; here none was found, which the configuration has to correct.
- **Saying the cold half was created, instead of asking first.** A retry would then fail on the cold half's config; asking first leaves no file of the repository to undo.
