# Decision 44: Reviewing maintenance before it runs

**A forget, an adoption, a prune and a check each have a preview, and a forget or an adoption started with its preview's selection runs only if it would act on exactly that selection** (recorded 2026-11-10, §4.2, §4.4, §7.3 step 4, I6). `POST /api/v1/repositories/{alias}/maintenance/preview` takes the body of a start and answers what the run would do: per plan the snapshots a forget would remove and what it leaves alone, the snapshots an adoption would rewrite, a prune's dry run (the packs it would mark, delete and bring back, the bytes, and the `keep-delete` wait of I2), whether a check reads data. It is a read like the snapshot listing: it takes no I7 slot, writes nothing to the operation log, and gives up on a repository that does not answer after `READ_TIMEOUT` (`repository-read-timed-out`, HTTP 504). A forget's and an adoption's preview carries a `selection`, the 64-bit FNV-1a fingerprint of the sorted snapshot IDs it names, as 16 hex digits; `POST …/maintenance` with that `selection` evaluates the selection again before it takes the slot and refuses with `maintenance-selection-changed` (HTTP 409) when it is not the same set, so another backup, another machine's forget or an edited policy between the review and the confirmation removes nothing. Without a `selection` a start selects as it finds the repository, as a schedule does; a `selection` on a prune, a check or a preview is `invalid-body`. `GET /api/v1/repositories/{alias}/groups` lists the history by owner for the page; a group lists at most `MAX_GROUP_SNAPSHOTS` (500) snapshots and a review at most `MAX_PREVIEW_SNAPSHOTS` (50), the real count beside each (§13.5). The approval threshold of §7.3 step 4 (more than N% of a group) is not built: every forget is confirmed by a person who saw its preview. Why: the dialog's promise is that what a person reviewed is what is removed (I6); a fingerprint costs the daemon no state and the request no list (decision 32), and a repository that changed is refused rather than deleted from. Not chosen: a stored preview (state to expire and to survive a restart), and sending the snapshot IDs back (a request that grows with the repository).
