# Decision 27: Profile interop: what an import refuses, what an export says

**An import refuses what it would have to guess at; an export is a profile the stock `rustic` reads, and says or refuses what rustic would do differently** (recorded 2026-11-10, §6.2). Settled: (1) a plan's ID is the slug of the entry's `name`, else its label, else the last folder of its first source, else `plan`, and any clash, with the configuration or inside the profile, is refused, never numbered; (2) one host for every plan, with no plans and no agent hostname in the configuration, becomes the agent's hostname, and a plan that names the agent's hostname drops it; (3) `RUSTIC_PASSWORD*`, `RUSTIC_REPOSITORY` and `RUSTIC_REPO_OPT_*` fill only what a profile leaves out, and are kept as references, never as values; (4) `keep-tags` and `keep-ids` are refused, because dropping them would let a forget remove what rustic keeps, and a key rustic itself refuses is refused, naming its path and line (`[repository]`, which rustic reads leniently, gets a notice); (5) every `${` a profile wrote into a repository value is escaped, so a profile can't make the configuration read a file, and a secret in a profile is kept as written with a warning that names the field; (6) an exported entry is named by the plan's ID, so a round trip gives the same plan, its forget has `group-by = ""` and one comma-joined `filter-tags` entry, and it never prunes; (7) a plan with no retention is exported, with a notice that rustic's `forget` refuses to run until a `keep-*` option is set; (8) a repository, hot repository or rclone connection string with a password or a secret piece is refused naming the key, an option with a user or a password in an address (with or without its scheme) is left out like any secret option, and the value is never shown; (9) a tag with a comma is refused naming the tag; (10) a non-empty `[snapshot-filter]` beside retention is refused, because rustic's forget then reaches fewer snapshots than a plan's does, except the filter an export writes, and so is `profile-substitute-env = true`; (11) a profile is bounded by what it can multiply or repeat: 100 000 items across the plans, 32 names in `use-profiles`, 200 different keys left out, and a value that stays under 64 KiB once escaped. Why: a profile is input nobody vetted, and a guess about what a setting means is how a forget removes snapshots a person meant to keep; the export is the way back to the stock CLI, and what it can't say in rustic's words has to be said, or it is found out when a forget does something else. Cost: a profile with a `keep-tags`, or a `[snapshot-filter]` and retention, has to be edited before it imports, and a repository with credentials in its address has to move them into options before it exports. The golden checks need `rustic` 0.11.4 and skip where it isn't installed, so CI runs them once a separate change installs it.
