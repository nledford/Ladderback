# Decision 46: The tooling's language

**The tooling (`scripts/`, the l10n expectations generator, the UI tests) is TypeScript that Node runs as it is, by stripping the types: no build step, nothing emitted, and `tsc --noEmit` in `just lint` is the only place the types are checked** (recorded 2026-11-10; #144). The scripts were JavaScript, so a wrong argument or a misspelt field showed only when a run reached it. Decided: (1) `tsconfig.json` at the root covers the three trees with `strict`, `noEmit`, `erasableSyntaxOnly` (only syntax Node can strip: no `enum`, no parameter properties, no `namespace`), `allowImportingTsExtensions` and `module: nodenext`, because Node needs the `.ts` in each import; and two options beyond what type stripping needs: `verbatimModuleSyntax`, so a type-only import must say `import type` and Node never loads a module for a name it strips, and `noUncheckedIndexedAccess`, so an index into an array or a record is `T | undefined` and a script that reads past its arguments or its parsed JSON has to say what happens then; (2) a root `package.json` with `type: module`, so Node and `tsc` treat `scripts/` and the generator as ES modules, and `engines.node >= 22.18.0`, the first LTS that strips types without a flag (Node prints an `ExperimentalWarning` until 24.12 and 25.2); it has no dependencies: `typescript` and `@types/node` are `ui-tests`' exact dev-dependencies; (3) the check holds the code to that minimum: `target` and `lib` are `es2024`, all of which Node 22 has, so a newer built-in such as `RegExp.escape` fails `tsc`, and `@types/node` follows the minimum's major, 22, so a `node:` API Node 22.18 lacks fails too; `lib` adds the DOM for the UI tests' `page.evaluate` callbacks, and the scripts see those types as well, the price of one check over three trees; (4) cucumber-js finds no `.ts` configuration by itself, so `ui-tests/cucumber.ts` is named with `--config` everywhere the UI tests run: `just test-ui`, the npm `test` script and `scripts/red-first.ts` (when the tree it checks has one); (5) `just lint` runs `tsc --project tsconfig.json`, after `_ui-deps` installs `ui-tests`' packages when they are missing or older than the lockfile, so the first `just lint` in a fresh worktree needs the network; (6) the UI tests' world finds the binary itself, `LADDERBACK_BIN` or else `debug/ladderback` under the target directory `cargo metadata` names, which replaces `test-ui`'s inline lookup and makes a bare `npm test` follow `CARGO_TARGET_DIR` (it needs `cargo` on the `PATH` when `LADDERBACK_BIN` is unset). Not chosen: a build step (`tsc` emitting JavaScript, or a bundler), which adds output to keep in step with its source for scripts that run once each, and JSDoc types over JavaScript, which `tsc` checks but Node never sees.
