# Decision 43: Dependency policy

**`cargo deny` checks advisories, licences, bans and sources against `deny.toml`; the licences are an allow list of permissive ones, and `chrono` is banned except as `suppaftp`'s dependency** (recorded 2026-11-10, §13.6). Licences: Apache-2.0 (also `WITH LLVM-exception`), MIT, MIT-0, BSD-2-Clause, BSD-3-Clause, ISC, BSL-1.0, CC0-1.0, CDLA-Permissive-2.0, Unicode-3.0, Unlicense and Zlib, all of which let a binary under MIT OR Apache-2.0 ship. No GPL, AGPL or LGPL: a crate that offers one of them as one choice of an `OR` (`self_cell`) is used under its permissive choice. MPL-2.0, file-level copyleft that binds only changes to the MPL files themselves, is allowed for one crate, `option-ext` (through `rustic_core`'s `dirs`), by name. The `chrono` ban is decision 22 made mechanical: `wrappers = ["suppaftp"]` lets it in only where `rustic_backend`'s OpenDAL FTP service needs it, so a direct use fails the check; `just architecture` still bans it from `domain` and `app`. Advisories fail, `unmaintained` and `yanked` included, and an advisory with no fix inside our requirements is ignored by ID with a reason (three so far: `libsqlite3-sys` and `rsa`, held by upstream pins, and `paste`, a compile-time macro of Leptos's). Duplicate versions only warn, and wildcard requirements fail. CI runs it in the `Dependencies (cargo-deny)` job, on pull requests and nightly; a failed nightly run opens an issue, or comments on the open one, as the nightly mutation run does. It is not a required check until the maintainer adds it. Why: a dependency that brings a vulnerability, a copyleft licence or a second time library should fail a check, not be found later; nightly, because advisories appear with no code change, and a scheduled run that only fails would go unseen. It checks every workspace package (`--workspace`), `web` included.
