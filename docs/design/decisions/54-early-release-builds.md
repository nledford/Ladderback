# Decision 54: Early release builds

**From M2, cargo-dist builds the release archives every night and on release PRs, and a smoke test checks each binary on clean systems; nothing is published until M5's release packaging** (recorded 2026-11-11). A release binary differs from a development build: no default features, the dist profile (release with thin LTO), the web UI built with `--release`, and the glibc of the machine that built it. Nothing built one before, so M5 would have met every problem at once.

- **Tool.** cargo-dist 0.34.0 (Apache-2.0 OR MIT), which §12 already names, installed by `scripts/install-dist.sh` from the official release with a pinned SHA-256 per host. It runs build-only, `dist build --artifacts=local --target <t>`, from our own `.github/workflows/release-builds.yml`. dist's generated workflow isn't used: it would write `.github/workflows/release.yml`, release-plz's file; it runs on every pull request and on tag pushes; and it uses a shared build cache and a `curl | sh` installer. `dist-workspace.toml` has no `ci` key, so dist neither writes nor checks one.
- **What it builds.** The `ladderback` package alone (`dist = false` for the workspace, `dist = true` in its `[package.metadata.dist]`; dist's `packages` key didn't limit the build), with `default-features = false`, which `just architecture` checks against the `Justfile`'s `release_flags`, and `precise-builds`, so the features are the package's own.
- **Targets.** `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu`, built on Ubuntu 22.04 runners, so the binary needs glibc 2.35 at most and runs on Debian 12, Ubuntu 22.04 and newer; the smoke test fails above 2.35. `aarch64-apple-darwin` only: dist can't build a universal macOS binary yet (axodotdev/cargo-dist#77). A published macOS archive also needs Developer ID signing and notarization (decision 71).
- **Smoke test.** `scripts/smoke-release.ts` (§12.1): the version, no pseudolocales or gallery, the dynamic libraries and glibc floor, `serve` with its UI, and one backup into a scratch repository, natively or in Debian 12, Ubuntu 22.04, Ubuntu 24.04 and Fedora containers pinned by digest.
- **Workflow.** Nightly, by hand, and on pull requests labelled `release`, which release-plz puts on each release PR. No build cache, read-only contents, archives kept 7 days as run artifacts, uploaded before the smoke test. A failed nightly run opens an issue from a separate job that alone holds `issues: write`. Not a required check.
- **wasm-bindgen on aarch64 Linux.** Its aarch64 Linux release is a gnu build that needs glibc 2.38, so on Ubuntu 22.04 trunk can't run the one it downloads; that job builds `wasm-bindgen-cli` at the `Cargo.lock` version from source, which trunk then finds on the `PATH`.
