# Decision 151: A paired machine maintains only under a live lease from its hub, and asks for its grants every 15 minutes

**From the moment it is paired, a machine runs a forget, a prune, a check or an adoption only while it holds a live lease on the repository from its hub, and is refused with `maintenance-no-lease` otherwise; a preview is never refused for want of one. It asks for its grants in a session at start, in every session that sends reports, and whenever 15 minutes have passed on its own clock since the last. Each answer replaces every lease it holds, its end moved onto the machine's clock from the moment the request left. A grant below the repository's epoch floor is refused and only logged.**

## Why

§7.3 says an agent maintains only while its lease holds, judged on the hub's time, and that a grant below the highest seen is refused (`epoch-lower`). [Decision 147](147-the-hub-decides-leases-on-each-report.md) decides the leases on the hub. This decision is the machine's side of the wire (§7.2, `ReposSnapshot`, `RepoGrants`, `ReleaseAck`, `Released`), so I1 holds end to end.

- **Gated from pairing.** A paired machine that hasn't heard a grant maintains nothing. Decision 147 left the agent ungated until the hub sends grants, which held while no hub sent any. With the wire built, a machine waiting for its first grant can't tell "not yet" from "another agent holds it": its hub may have granted the repository elsewhere while it was offline. Nobody pruning is the safe direction (§7.3). A machine that isn't paired maintains what it asks for, as before, and so does a build without the `hub` feature, which can't pair.
- **Previews ask for nothing.** A preview of a forget, a prune, a check or an adoption changes nothing and takes no lock that writes, so a machine without a lease still shows what a run would do.
- **The lease's end on the machine's clock.** A grant carries the hub's clock when it signed it and the lease's expiry on that clock. The machine keeps `asked_at + (expires_at − signed_at)`, where `asked_at` is its own clock just before the request left. The hub signs after that, so the machine's lease ends no later than the hub's, whatever the two clocks read. The end is wall-clock time, so time asleep counts, and it is kept in SQLite (`agent_leases`), so a restart keeps it. A lease is judged at the wall clock, but never earlier than the monotonic time passed since the daemon last took its grants, so a clock set back doesn't lengthen it.
- **Every answer replaces every lease.** `RepoGrants` names every lease the hub counts the machine as holding. A lease it doesn't name is let go at once: the hub refused or stopped renewing it, or a person moved the repository.
- **15 minutes.** A lease lives 7 days and the hub counts it an hour past that (decision 147). Asking every 15 minutes keeps a lease the hub renews from ever running out while the hub can be reached, at a small cost: one signed message each way. A clock set back counts as time passed, so a machine whose clock jumped back still asks.
- **Let go, then release, then report.** A lease on a repository the configuration no longer asks `local` for is let go, then released (`ReleaseAck`) before the report; the hub answers `Released` for that repository and epoch. Letting go first means a release whose answer is lost leaves nothing to maintain under. A lease whose repository has a maintenance running here is neither let go nor released: the hub counts it until it runs out, so it grants the repository to no other machine mid-run. The hub answers every release alike, one it refuses too.
- **Epoch floors.** The highest lease seen for each repository, by recovery number, generation and epoch, is kept in `agent_epoch_floors`. It only rises, and outlives the lease it came from. A grant below it is refused, and the machine holds no lease on that repository until a grant at or above it.
- **`epoch-lower` is a log line.** The refusal is what keeps I1: the machine runs nothing under a grant from a rewound hub. Nothing on the machine shows it yet, so it is a warning in the daemon's log naming the repository and both leases, not an error code. `maintenance-no-lease` is the code a refused run returns.

## Consequences

- A machine that pairs with a hub stops maintaining until its first session gets a grant, and maintains nothing while the hub refuses it or grants the repository to another machine.
- A machine that can't reach its hub keeps maintaining until its lease ends, then stops: at most 7 days after its last renewal, on the hub's time.
- `ReposSnapshot` always says `others_snapshots: false`, since the machine doesn't yet know during a session which agents' snapshots a repository holds (#1465). Another agent's report of the repository still refuses a claim; a machine that backs up to it without reporting to this hub doesn't.
- `RepoGrants` carries no `owner`, `keep_delete` or `prune_margin`, and `ReposSnapshot` no `alias`, yet: every grant is the receiving machine's own lease, and the deadline inputs come with the owner prune guard (#573).
- A configuration the machine can't read ends the session (`SyncFailure::Config`) before anything is asked, and the leases it holds stay as they were until they run out.
- A hub that doesn't decide ownership answers neither `ReposSnapshot` nor `ReleaseAck`. The machine then waits the 15 seconds it gives each answer, the session fails, and it holds no lease from that hub.
- `ReposSnapshot` names at most 21 repositories, the first by ID, so it and its `RepoGrants` each fit a 4096-byte frame. A machine that uses more holds no lease on the others.
- The lease is checked when a run starts, not while it runs. A prune started just before its lease ends can run past the hub's hour of grace, when another machine may hold the repository. The owner prune guard's deadline (#573) is where that closes.
- A run checks its lease before it takes its place in the operation log, so a session in that gap may release the lease of a run about to start. The gap is milliseconds; the release names a repository the configuration no longer asks this machine to maintain.
- A clock set back while the daemon was stopped lengthens a lease by as much until a session takes its grants again, which the daemon asks for as it starts; one that can't reach its hub keeps the longer lease.
- A scheduled forget, prune or check that is refused leaves only a log line. A machine whose leases lapsed, because it was away from a hub it can reach only on its LAN for over 7 days or its hub is gone, stops its scheduled maintenance silently. #1473 adds a visible paused state and an alert.
