# Decision 35: The zone of an instant with no zone

**UTC by default in the formatter, on both hosts; a page passes the viewer's zone, and the web UI always passes the browser's own** (recorded 2026-11-10, §8.4; #62). The `icu` and `browser-intl` hosts read an instant with no zone, or a zone nobody has, as UTC, and the shared table of expectations requires it; the web UI passes `Intl.DateTimeFormat().resolvedOptions().timeZone` (`l10n::viewer_zone`) with every instant it shows. Why: a formatter that read the viewer's zone would give the daemon and the browser two readings of one message, and a table of expectations that held for only one of them; a page that means the viewer's zone says so, in one place. The other way, the browser host leaving `timeZone` unset, would have needed per-host expectations. `just test-wasm` pins `TZ` to a zone that is not UTC, so a host that read no zone as the viewer's fails the table.
