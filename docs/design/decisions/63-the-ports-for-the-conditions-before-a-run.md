# Decision 63: The ports for the conditions before a run

**Two small ports, `PowerSupply` and `Network`, and monotonic time on `Clock`; no single `Platform` port** (recorded 2026-11-11, §3.2, §5; #273). `PowerSupply::source` answers AC power or battery, `Network::is_online` whether the machine has a working connection, each a typed `PlatformError` when the platform can't say. The wake check needs no port of its own: `Clock` gains `monotonic()` and a monotonic `sleep`, and the `WakeDetector` rule lives in `domain`.

Why:

- **One port per question,** as the other ports are (`SecretResolver`, `HookRunner`, `Retention`): a use case takes only what it asks, a fake is one scripted answer, and each contract suite is small. A plan's AC power check doesn't need the network, and the catch-up's network wait doesn't need the power supply. The metered-connection condition of §5 joins `Network` when it is built.
- **The wake is a clock's question, not the platform's.** §3.2 already gives `Clock` monotonic time and puts the wake check in `app`, driven by `Clock`; the rule (a gap of more than 2 min between wall-clock and monotonic time over a 30 s sample) is pure and lives in `domain::execution::wake`. A third port would only wrap `Instant`. `SystemClock` reads `std::time::Instant`, which stands still while the machine sleeps on Linux (CLOCK_MONOTONIC) and macOS (CLOCK_UPTIME_RAW); the standard library documents that as the platform's behaviour, not a promise, so a toolchain whose `Instant` counted time asleep would hide every wake.
- **A source the platform can't report never holds a run back.** An unreadable or unrecognized power source lets an AC-only plan run, and a network state that can't be read ends the network wait at once: a missed backup costs more than some battery or a failed first try. The answer is never a guess: the adapters return `Unrecognized` for what they don't know, and the use case decides.
- **Network readiness is the machine's, not the repository host's.** §5 asked that the repository host resolve. Which host a repository needs is a question of each backend (sftp, rest, opendal options, rclone remotes), and a local repository needs none; the port answers whether the machine is online, and the scheduler (#274) decides which runs wait. The Linux adapter counts an interface other than loopback that is switched on (`IFF_UP` in `flags`) and whose `operstate` is `up`, or `unknown` with a carrier, as tunnels and point-to-point links report; sysfs `flags` never holds `IFF_RUNNING`, which the kernel works out for `ioctl` and netlink only. A bridge with containers counts too, and then the run starts as it would have without the wait.
- **No new crate.** Linux reads sysfs, with the folder injectable so the contract suites run on any machine. IOKit would need FFI (`unsafe_code` is forbidden) or a crate, so macOS runs `pmset -g batt` and `scutil --nwi` by absolute path, with no environment, through the spawn gate (decision 58), bounded in output (64 KiB) and in time (5 s for the whole call, the wait for the gate included). Both adapters run on every platform in the tests, against made-up folders and stand-in programs.
